# DesignSystem

A Flutter design-system monorepo: **DTCG design tokens → generated Dart →
theme layer → `App*` components**, with golden tests, widget previews and a
Widgetbook catalog. The architecture follows
[`docs/research/flutter-design-system.md`](docs/research/flutter-design-system.md)
(sections 3 and 4).

- Flutter **3.47.5** / Dart **3.13**, Dart **pub workspaces** + **Melos 7**
- Built on the standalone **`material_ui`** package (see [Material dependency](#material-dependency))
- Token source of truth: W3C **DTCG JSON** in [`tokens/`](tokens/), generated by a
  pure-Dart tool (no Node/Style Dictionary needed)

## Layout

```
DesignSystem/
├── pubspec.yaml              # workspace root + melos scripts
├── analysis_options.yaml     # shared lints (flutter_lints + stricter rules)
├── CLAUDE.md                 # rules for Claude Code in this repo
├── tokens/                   # DTCG JSON — source of truth
│   ├── primitives.json       #   tier 1: palette, space, radius, font sizes…
│   ├── semantic.json         #   tier 2: spacing/radius/size/typography roles
│   ├── semantic.light.json   #   tier 2: themed colours (light)
│   ├── semantic.dark.json    #   tier 2: themed colours (dark)
│   └── component.json        #   tier 3: button/card specifics
├── tool/gen_tokens.dart      # tokens/*.json → *.g.dart (+ --check for CI)
├── packages/
│   ├── ds_tokens/            # GENERATED constants (package:flutter/widgets.dart only)
│   ├── ds_foundation/        # ThemeExtensions, AppTheme.light()/dark(), context.colors…
│   └── ds_components/        # AppButton, AppCard (+ tests, goldens, @Previews)
├── apps/
│   ├── example/              # minimal consumer app with a light/dark toggle
│   └── widgetbook/           # Widgetbook catalog (web)
├── docs/research/            # background research
└── .github/workflows/ci.yml  # format → analyze → token check → tests → widgetbook build
```

Dependency direction: `ds_tokens → ds_foundation → ds_components → apps`.
Apps import `package:ds_components/ds_components.dart`, which re-exports
`ds_foundation` (`AppTheme`, `context.colors`, …).

## Quick start

```sh
flutter pub get                          # resolves the whole workspace (one lockfile)

dart run tool/gen_tokens.dart            # regenerate tokens
dart format .
flutter analyze .
dart run melos run test --no-select      # tests in every package/app

cd apps/example && flutter run           # example app (android, ios, web)
cd apps/widgetbook && flutter run -d chrome   # component catalog
```

Melos scripts (`dart run melos run <name>`): `analyze`, `test`,
`test:update-goldens`, `gen-tokens`, `gen-tokens:check`, `format`,
`format:check`. Melos is a dev dependency of the workspace root, so no global
activation is needed.

## Using the design system

```dart
import 'package:ds_components/ds_components.dart';
import 'package:material_ui/material_ui.dart';

MaterialApp(
  theme: AppTheme.light(),
  darkTheme: AppTheme.dark(),
  home: Builder(
    builder: (context) => Padding(
      padding: EdgeInsetsDirectional.all(context.spacing.md),
      child: AppButton.primary(label: 'Save', onPressed: () {}),
    ),
  ),
);
```

- `AppTheme` maps tokens onto `ColorScheme`/`TextTheme` where Material has a
  slot, and attaches `AppColors`, `AppSpacing`, `AppRadius`, `AppTypography`
  as `ThemeExtension`s (with `copyWith`/`lerp`, so theme switches animate).
- Read them with `context.colors`, `context.spacing`, `context.radius`,
  `context.typography`.

## Changing a token end-to-end

Example: make the light-theme primary colour darker.

1. Edit the JSON — tokens are DTCG, aliases use `{group.token}`:
   ```jsonc
   // tokens/semantic.light.json
   "primary": { "$value": "{color.blue.700}" }
   ```
   (New raw values go into `primitives.json`; themed colours must exist in
   **both** `semantic.light.json` and `semantic.dark.json`.)
2. Regenerate: `dart run tool/gen_tokens.dart`. This rewrites
   `packages/ds_tokens/lib/src/*.g.dart` and
   `packages/ds_foundation/lib/src/generated/app_colors.g.dart`
   (files headed `// GENERATED – do not edit.`).
3. Run the tests. Golden tests will fail where pixels changed — inspect, then
   refresh them deliberately: `dart run melos run test:update-goldens --no-select`.
4. Commit JSON, generated Dart and updated goldens together. CI runs
   `dart run tool/gen_tokens.dart --check` and fails if they drift.

Generator details: groups' `$type` is inherited; supported types are
`color` (hex string or DTCG colour object with `alpha`), `dimension`
(`"16px"`, `"1rem"` or `{value, unit}`), `number`, `fontWeight`, `duration`
and `typography`. Aliases to static tokens are emitted as references
(`ColorTokens.light.primary` → `PrimitiveColor.blue600`) so the tier chain is
visible in code. Cycles, unknown aliases, type mismatches and light/dark key
mismatches are hard errors.

## Syncing with Claude Design / Figma

`tokens/*.json` is the interchange point between design tools and code:

- **Claude Design** (claude.ai/design): bring designs in via its
  **"Send to Claude Code"** hand-off, or export its tokens. Claude Code then
  maps the values onto `tokens/*.json` following the tier structure in
  [`CLAUDE.md`](CLAUDE.md), runs the generator and updates goldens.
- **Figma Variables**: export with a DTCG export plugin (e.g. *Token to
  Code*, *Variables to Flutter/Dart Export*) — primitives collection →
  `primitives.json`, semantic collection modes → `semantic.light.json` /
  `semantic.dark.json` — then run `dart run tool/gen_tokens.dart`.

In both cases, review the JSON diff (names stay stable, values change), let
CI's `--check` and golden tests catch unintended changes, and never paste raw
values into widgets.

## Material dependency

The research recommends the standalone `material_ui` package over the frozen,
soon-deprecated `package:flutter/material.dart`. `material_ui` ^1.5.0 resolves
cleanly with Flutter 3.47.5, so **every package, app and test in this repo
imports `package:material_ui/material_ui.dart`**. The two libraries define
distinct `Theme`/`ThemeData` types, so mixing them breaks theme lookup —
`ds_components/test/token_hygiene_test.dart` guards against stray
`flutter/material` imports.

Consumers of this design system must also use `material_ui`'s
`MaterialApp`/`Theme`. Some tooling is still on `flutter/material` internally
(alchemist 0.14, Widgetbook 3.x, the widget-preview shell); in those places we
provide our own `material_ui` `Theme` explicitly around the content.

## Catalog, previews and tests

- **Widgetbook** (`apps/widgetbook`, `widgetbook` 3.25): one use case per
  component with knobs, a light/dark `ThemeAddon`, text-scale and alignment
  addons. Build for hosting with `flutter build web` (CI does this).
- **Widget previews**: `packages/ds_components/lib/src/previews.dart` declares
  `@Preview`s (light, dark, 2× text). Run `flutter widget-preview start` in
  `packages/ds_components`.
- **Golden tests** with `alchemist` in CI mode (platform-agnostic: text drawn
  as blocks) for `AppButton`: light/dark × text scale 1.0/2.0 × variants,
  states and sizes. PNGs live in `packages/ds_components/test/goldens/ci/`.
- **Widget tests** cover behaviour and accessibility guidelines (tap target,
  labels, text contrast) in both themes.
